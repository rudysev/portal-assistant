# wakeword-bench — comparing wake-word detectors for "hey jarvis" (macOS)

A standalone macOS (Apple Silicon) harness that scores several wake-word detectors on the
**same** labeled corpus, so we can see whether a purpose-built keyword spotter beats the
shipping **Vosk** grammar approach on detection rate and/or false accepts.

Sibling of `tools/latency-bench/` (which measures on-device latency). This one runs entirely
on the Mac against pre-generated audio, so results are comparable and repeatable.

## Detectors

| Detector | How it spots "hey jarvis" | Training needed | Notes |
|---|---|---|---|
| **vosk** (baseline) | grammar-restricted Kaldi + our `WakeMatcher` gates | no | replicates the device path exactly (see below) |
| **openwakeword** | pretrained `hey_jarvis` model (onnxruntime) | no | ⚠ trained on Piper TTS — in-distribution bias |
| **sherpa-kws** | open-vocabulary zipformer KWS + keyword file | no | small 3.3M model |
| **porcupine** | built-in `jarvis` keyword | no | needs a free access key; keyword `jarvis`, not the phrase |
| **livekit** | trained ONNX (openWakeWord-compatible) | **yes** | Phase 2b — see `train/README.md` |
| **microwakeword** | trained TFLite (MCU-class) | **yes** | Phase 2b — see `train/README.md` |

Each detector is a **thin adapter** (`detectors/*.py`) over the library's own API/example
code — no library's detection logic is reimplemented. The only ported code is *our own*
`WakeMatcher` decision logic (`wakematcher.py`), needed to make the Vosk baseline faithful.

## The Vosk baseline is a faithful replica

Mirrors `portal-commons` `WakeRecognizer.kt` + `WakeMatcher.kt`, pinned to
**`origin/feat/foreground-wake-detection`** (the tested state):

- same model **`vosk-model-en-us-0.22-lgraph`** (the app's `MODEL_URL`), 16 kHz mono
- grammar-restricted `KaldiRecognizer(model, 16000, '["hey jarvis","jarvis","hey","[unk]"]')`, `SetWords(True)`
- 100 ms (3200-byte) frames, ~1 s silence warm-up after reset
- **stock** `rule2.min-trailing-silence=0.5` (the local `0.3` patch is untested → left out;
  pass `endpoint_silence=0.3` to A/B it)
- the pure `WakeMatcher` gates (lead present, no `[unk]`, ≤3 words, lead ≥0.80, keyword
  ≥0.60, no rival) — **verified** against the Kotlin unit tests:

```bash
python -m pytest tests/ -q        # 42/42 — proves the port matches WakeMatcherTest.kt
```

## Corpus

Generated by `data/` (macOS `say` TTS, then numpy/scipy augmentation):

- **positives** — "hey jarvis" across many natural voices × speaking rates, each expanded
  into conditions: `clean`, `reverb` (synthetic RIR), `quiet` (0.5× ≈ the ~4 m room-distance
  proxy), `noisy@{20,10,5,0}dB` (pink noise). Padded with a known phrase-end offset (latency).
- **near_miss** — confusable phrases (`hey jeremy`, `hi jarvis`, `a jarvis`, `okay jarvis`,
  bare `jarvis`, rival `hey alexa`, …). Any fire here is a false accept.
- **background** — minutes of continuous non-wake speech → **false accepts per hour**.
- **silence** — pure silence / noise-only.

Why `say` and not Piper: openWakeWord's `hey_jarvis` was trained on **Piper** TTS, so testing
on Piper would hand it an in-distribution advantage. `say` (Apple neural TTS) is a different
distribution — fairer. Piper can be enabled for more speaker diversity, but re-introduces
that bias. **Either way these are TTS, not real room speech — treat results as relative.**

## Run it

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e .                              # or: pip install -r <the deps in pyproject>

python -m pytest tests/ -q                    # 1. verify the Vosk baseline port
python -m data.fetch_assets --all             # 2. download Vosk + sherpa models (~200 MB)
python -m data.manifest --role test           # 3. generate the corpus (+ --quick for a smoke test)
python bench.py --detectors vosk oww sherpa porcupine   # 4. run detectors → results/*.jsonl
python analyze.py                             # 5. comparison table → results/summary.md
```

Porcupine: set `PICOVOICE_ACCESS_KEY` (free at console.picovoice.ai) or it's skipped.
Trained detectors: see `train/README.md`, then `python bench.py --detectors livekit mww`.

## Metrics (`analyze.py`)

- **recall** overall + per condition (clean/reverb/quiet/noisy@SNR)
- **nearFA** — % of confusable clips that fired
- **FA/hr** — background false accepts per hour (headline precision metric)
- **latP50/P90** — fire offset − phrase-end (offset-exact, unlike the device's acoustic timing)
- **RTF** — processing time ÷ audio duration (CPU cost; lower = cheaper)
- **Recall @ FA/hour target** — threshold sweep for continuous-score detectors (openWakeWord),
  the only fair cross-library operating point since each library's default threshold differs.

## Example finding

On the initial run the harness already surfaced a real Vosk weakness: **"hey jeremy" decodes
as "hey jarvis"** under the grammar bias (≈86% of those clips fire), where openWakeWord and
sherpa reject it (0% nearFA). Note the Kotlin `WakeMatcherTest` assumes Vosk *outputs*
"jeremy" for that phrase — acoustically it doesn't; the grammar forces it onto "jarvis". The
benchmark catches the gap between the unit-test model and real acoustic behavior.

## Caveats

- TTS ≠ real room speech; openWakeWord has a residual TTS-training advantage.
- Porcupine grades the keyword `jarvis`, not the full phrase (custom `hey jarvis` .ppn = paid).
- The PyPI `vosk` build differs slightly from the app's `vosk-android:0.3.75`; same model.
- Synthetic RIR/pink-noise approximate real rooms/backgrounds; point augment.py at real RIR /
  MUSAN wavs for higher fidelity.
