# wakeword-bench — wake-word detection benchmarks for "hey jarvis"

Primary workflow now: the **2×2 recall isolation matrix** (openWakeWord only), which separates
**model quality** from **mic / post-processing** using the same labelled clip list on Mac and Portal.

Historical multi-detector comparison (Vosk / sherpa / Porcupine / …) remains below for archive runs.

---

## Recall isolation matrix (2×2)

Same `say`-generated WAVs, four paths:

| | **File inject** (PCM → detector, no mic) | **Acoustic** (Mac speaker → mic) |
|--|--|--|
| **Mac** | **A** — model + Mac ONNX Runtime | **B** — Mac mic + room + model *(control)* |
| **Portal** | **C** — model + Android ORT / app path | **D** — Portal mic + `VOICE_RECOGNITION` + model |

```
corpus (say TTS WAVs)
   ├─► A  Mac file inject
   ├─► B  Mac acoustic   (speaker @ 65%)
   ├─► C  Portal file inject  (portal-wake WakeBenchmark)
   └─► D  Portal acoustic     (assistant wakebench @ 65%)
              └─► results/MATRIX.md  (A−C / C−D / A−D deltas)
```

### How to read the deltas

| Delta | Meaning | Action if large |
|-------|---------|-----------------|
| **A ≈ C** | Runtimes agree — model ceiling is trustworthy on-device | — |
| **C ≫ D** | Portal mic / FX / room / speaker coupling | Front-end: ducking, capture source, placement |
| **A ≫ C** | Android path / asset / frame mismatch | Fix port before training |
| **A ≈ D** | Model is the bottleneck end-to-end | Train / phrase / architecture |

Acoustic cells also include **speaker, volume, distance, and room** — not “mic alone.” Fix those in the script (volume **65%**, screen stay-on, `VOICE_RECOGNITION`). Cell **B** is a control, not a Portal product proxy.

Kitchen / same-device playback remains a separate fifth condition (`device_bench_kitchen.sh`) — do not mix it into this matrix.

### Run the matrix

From `tools/wakeword-bench/` (branch `feature/oww-recall-matrix` or later):

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e .

# One-shot: corpus (if needed) → clip list → A→B→C→D → MATRIX.md
./matrix/run_matrix.sh                  # smoke list (~97 clips)
./matrix/run_matrix.sh --cells A,C      # Mac+Portal file inject only (no mic / no device speaker)
./matrix/run_matrix.sh --full           # all manifest clips
./matrix/run_matrix.sh --quick          # tiny wiring check

# Acoustic volume (Mac output), default 65:
MATRIX_VOLUME=65 ./matrix/run_matrix.sh --cells B,D
```

**Device cells (C/D)** need a connected Portal, `ANDROID_HOME`, and:

- **C:** builds/installs `portal-wake` + androidTest (`WakeBenchmark` oWW file inject).
- **D:** installs/runs `portal-assistant` with `files/wakebench` (score-only, no conversation). Prefer
  `./setup.sh` / provisioner so `RECORD_AUDIO` is granted.

Outputs:

- `results/matrix_{A,B,C,D}_*.csv` — per-clip peak / fired
- `results/MATRIX.md` + `results/matrix_summary.json` — table + deltas

Clip list format (`matrix/clips_smoke.txt`):

```
label|category|condition|relpath
00054_Sandy_200_clean.wav|positive|clean|corpus/test/positive/00054_Sandy_200_clean.wav
```

Rebuild lists after regenerating the corpus: `python -m matrix.build_clip_list` (`--full` / `--quick`).

### Fixed acoustic setup (B / D)

- Mac **output volume 65%** (`MATRIX_VOLUME`, also `device_bench.sh`)
- Portal on screen, stay-awake enabled (Android 10 silences the mic when the display dozes)
- Capture: `VOICE_RECOGNITION` (product default)
- Same physical Mac↔Portal placement across runs; note distance in your lab log
- Threshold **0.5** (product default); sweeps live in analysis only

### When to train vs fix capture

1. Tag real misses with the matrix (and near-miss logs).
2. If **C ≫ D** → capture / ducking / placement first.
3. If **A ≈ D** (and A ≈ C) → fine-tune an oWW head on Portal-mic data.
4. Kitchen same-device music → separate interferer bench, not this matrix.

## Multi-detector Mac harness (archive)

A standalone macOS harness that scores several wake-word detectors on the **same** labelled
corpus (Vosk, openWakeWord, sherpa, Porcupine, optional trained livekit / microWakeWord).

### Detectors

| Detector | How it spots "hey jarvis" | Training needed | Notes |
|---|---|---|---|
| **vosk** (baseline) | grammar-restricted Kaldi + `WakeMatcher` gates | no | historical device path |
| **openwakeword** | pretrained `hey_jarvis` model (onnxruntime) | no | ⚠ trained on Piper TTS |
| **sherpa-kws** | open-vocabulary zipformer KWS + keyword file | no | small 3.3M model |
| **porcupine** | built-in `jarvis` keyword | no | needs a free access key |
| **livekit** | trained ONNX (openWakeWord-compatible) | **yes** | see `train/README.md` |
| **microwakeword** | trained TFLite (MCU-class) | **yes** | see `train/README.md` |

### Corpus

Generated by `data/` (macOS `say` TTS, then numpy/scipy augmentation):

- **positives** — "hey jarvis" across voices × rates × conditions (`clean`, `reverb`, `quiet`, `noisy@SNR`)
- **near_miss** — confusable phrases (any fire = false accept)
- **background** / **silence** — FA/hr and noise floor

Why `say` and not Piper: openWakeWord's `hey_jarvis` was trained on **Piper** — testing on Piper
would hand it an in-distribution advantage. **TTS ≠ real room speech — treat results as relative.**

```bash
python -m data.manifest --role test           # or --quick / --large
python bench.py --detectors oww               # → results/*.jsonl
python analyze.py                             # → results/summary.md
```

### Metrics (`analyze.py`)

- **recall** overall + per condition
- **nearFA** — % of confusable clips that fired
- **FA/hr** — background false accepts per hour
- **latP50/P90**, **RTF**, recall @ FA/hour (DET sweep)

### Caveats

- TTS ≠ real room speech; openWakeWord has a residual TTS-training advantage.
- Porcupine grades the keyword `jarvis`, not the full phrase.
- Synthetic RIR/pink-noise approximate real rooms; point `augment.py` at real RIR / MUSAN for higher fidelity.
